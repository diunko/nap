# Test architect response — 0320-session-and-render

## What I produced

`0320-session-and-render.test.md` — 16 test cases across 3 areas.

## Summary

### Session persistence (8 tests: SP-01 through SP-08)

Covers the full save/restore round-trip for every new field in ui-state.json: focusedCardSlug, activeTerminalId, leftTabs, rightTabs, activeLeftTabId/activeRightTabId, leftPaneRenderMode.

The hardest seam: **tab ID reconstruction**. Tab IDs are transient (generated by `nextTabId()`), so they can't round-trip. Restore must match by path and reconstruct IDs. SP-03 tests this explicitly.

Ghost tabs (SP-05 through SP-07) are the biggest new concept. The seam is between file:read failing and the tab still being present in the bar. SP-06 is the only medium test here — needs real filesystem events to prove the dir watcher brings ghost tabs back to life.

### Rendered mode refresh (3 tests: RR-01 through RR-03)

The core bug is a timing seam: when activeFilePath changes, the rendered mode effect fires, but the Monaco model still has old content (file load is async). The existing code at ContentPane.tsx:449 depends on `[leftPaneRenderMode, activeFilePath, ...]` — the effect fires, reads `model.getValue()`, but the model hasn't been updated yet.

The fix needs to either:
1. Have the rendered effect wait for the model to be current, or
2. Depend on model content version, not just activeFilePath

RR-01 (medium) tests this directly: switch tabs in rendered mode, assert new content appears.

### Scroll sync (6 tests: SS-01 through SS-06)

The key insight: `data-source-line` is block-level, not line-level. The match is always approximate. SS-05 tests the closest-match algorithm as a pure function (small test) — should prefer the block that CONTAINS the cursor line (largest `data-source-line ≤ N`), not the nearest by absolute distance.

SS-02 tests the off-screen cursor fallback: when cursor y is negative or > viewport height, use `getVisibleRanges()[0].startLineNumber` as anchor with screen y = 0.

SS-04 (round-trip) proves the toggle-twice invariant: cursor should return to within ±5 lines of original. Drift is expected but bounded.

## Findings for the architect

1. **Tab ID transience** — the biggest design question. Saved tab IDs will be invalid on restore. The restore code needs to create fresh IDs and re-wire activeLeftTabId/activeRightTabId by path lookup, not by saved ID.

2. **Rendered re-render timing** — the existing effect deps look correct (`[leftPaneRenderMode, activeFilePath, ...]`) but the model content is stale when the effect runs. The `onDidChangeContent` listener at ContentPane.tsx:457 should catch it, BUT that disposable is created from the current model ref, and on tab switch the model ref changes. The disposable needs to be re-created on the new model.

3. **Ghost tab watcher scope** — the spec says "watch parent directory and filter by filename." The existing ContentFileWatcher watches a single file. Ghost tabs need to watch the parent dir for their specific filename. This is a new watcher pattern — not a single-file watch.
