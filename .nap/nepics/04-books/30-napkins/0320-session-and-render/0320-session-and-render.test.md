# 0320 — test architecture

Three areas. Each test targets a seam between subsystems — where state crosses a boundary or two modules hand off.

## 1. Session persistence

### T-0320-SP-01: Save round-trip — focusedCardSlug

**Flow:** Store state → persistUiState → loadPersistedUiState → store state
**Subsystems:** zustand store ↔ electronAPI.saveUiState / loadUiState
**Expected:** `focusedCardSlug` saved on quit, restored on start. If slug matches a napkin/architect in model → `expandCard(slug)`. If not found → ignored, no card focused.
**Where it breaks:** Slug saved as string but model napkins not loaded yet when restore runs. Restore must happen AFTER model snapshot.
**Size:** Small
**Verification:** Set `focusedCardSlug` in store, call persistUiState, mock `loadUiState` to return saved value, call `loadPersistedUiState`, assert store matches. Also test the miss case: saved slug doesn't match any napkin → `focusedCardSlug` stays null.

### T-0320-SP-02: Save round-trip — activeTerminalId

**Flow:** Store → save → restore → setActiveTerminal
**Subsystems:** zustand store ↔ ui-state.json ↔ model (agent lookup by UUID)
**Expected:** `activeTerminalId` (a `cc_session_uuid`) saved, restored. On restore: find agent with that UUID in model. Found → `setActiveTerminal(uuid)`. Not found (agent deleted) → ignore.
**Where it breaks:** Agent archived → successor gets fresh UUID. Saved UUID points to old (archived) agent. Should still find it and show successor prompt (existing behavior), not crash.
**Size:** Small
**Verification:** Save terminal UUID, restore with model containing matching agent → assert terminal set. Restore with empty model → assert terminal null.

### T-0320-SP-03: Save round-trip — leftTabs + activeLeftTabId

**Flow:** Store → save leftTabs array → restore → re-create tabs in order
**Subsystems:** zustand store ↔ ui-state.json ↔ file:read (content load)
**Expected:** Tabs restored in saved order. Pinned/ephemeral state preserved. Active tab restored. Each tab triggers file:read for content.
**Where it breaks:** Tab ordering not preserved (array vs map). Active tab ID is transient (generated by `nextTabId()`) — can't match by ID across restarts. Must match by path or reconstruct IDs.
**Size:** Small
**Verification:** Create 3 tabs (2 pinned, 1 ephemeral) → save → restore → assert order, paths, ephemeral flags match. Assert activeLeftTabId points to correct tab (by path, not by old ID).

### T-0320-SP-04: Save round-trip — rightTabs + terminal reconstruction

**Flow:** Store → save rightTabs (file tabs only, not terminal sentinel) → restore → reconstruct terminal from activeTerminalId
**Subsystems:** zustand store ↔ ui-state.json
**Expected:** Terminal tab `__terminal__` is NOT saved in rightTabs — it's reconstructed from `activeTerminalId`. Only file tabs saved. On restore: create terminal sentinel first, then file tabs.
**Where it breaks:** If terminal sentinel is accidentally saved and restored, there could be duplicate `__terminal__` tabs. Or if reconstruction order is wrong: file tabs created before terminal → terminal overwrites active tab.
**Size:** Small
**Verification:** Set up right pane with terminal + 2 code files → save → assert `__terminal__` not in saved rightTabs. Restore → assert terminal sentinel exists at position 0, code tabs follow.

### T-0320-SP-05: Ghost tab — file missing on restore

**Flow:** Restore tab → file:read fails → create ghost tab
**Subsystems:** zustand store ↔ file:read IPC ↔ tab model
**Expected:** Tab stays in bar with `ghost: true`. Title grayed (opacity 0.4, italic). Editor area shows "file not found" placeholder. No crash, no silent removal.
**Where it breaks:** file:read rejection not caught → restore aborts midway, remaining tabs lost. Or ghost tab treated as active file → attempts to create Monaco model from null content.
**Size:** Small
**Verification:** Mock file:read to reject for one path, succeed for others. Restore 3 tabs (middle one missing) → assert 3 tabs in bar, middle has `ghost: true`, others have content. Assert `activeFilePath` is NOT the ghost tab's path (skip to next live tab or stay on previously active).

### T-0320-SP-06: Ghost tab — file reappears (dir watcher)

**Flow:** Ghost tab exists → file watcher fires "created" event → ghost becomes live tab
**Subsystems:** ghost tab state ↔ dir watcher (watching parent dir) ↔ file:read
**Expected:** When the file at ghost tab's path reappears, watcher fires → tab reloads content → `ghost` flag cleared → tab renders normally.
**Where it breaks:** Watcher watches the file path (which doesn't exist) instead of the parent directory. Or watcher fires but ghost tab isn't checking for its specific filename. Or race: file appears and disappears rapidly — ghost should only un-ghost when read succeeds.
**Size:** Medium — needs real filesystem events
**Verification:** Create ghost tab for missing file. Write file to that path on disk. Assert watcher fires, ghost flag clears, content loads. Delete file again → ghost returns.

### T-0320-SP-07: Restore ordering — ghost tabs interspersed with live tabs

**Flow:** Restore leftTabs array with mix of live and ghost paths
**Subsystems:** tab restore loop ↔ file:read ↔ tab model
**Expected:** Tabs appear in saved order regardless of which are ghost. Tab indices preserved. Active tab selection skips ghost tabs if the saved active tab is ghost.
**Where it breaks:** Async file reads resolve out of order → tabs appear in wrong order. Or all tabs created, then ghosts removed and re-added → order scrambled.
**Size:** Small
**Verification:** Save tabs [A:live, B:ghost, C:live, D:ghost, E:live]. Restore → assert exact ordering. Assert active tab is first live tab if saved active was B (ghost).

### T-0320-SP-08: leftPaneRenderMode persistence

**Flow:** Store → save → restore
**Subsystems:** zustand store ↔ ui-state.json
**Expected:** If user quits in rendered mode, app restarts in rendered mode.
**Where it breaks:** Already implemented (existing test RM-07 covers this). Include here for completeness — verify it survives alongside the new fields.
**Size:** Small
**Verification:** Existing test RM-07 covers. Extend to assert it persists alongside focusedCardSlug, tabs, etc.

## 2. Rendered mode refresh on tab switch

### T-0320-RR-01: Tab switch re-renders when mode is rendered

**Flow:** leftPaneRenderMode=rendered → openDoc(newPath) → activeFilePath changes → file loads → rendered HTML updates
**Subsystems:** store (activeFilePath) → ContentPane effect → file:read → Monaco model → renderMarkdown → DOM
**Expected:** Rendered view shows new file's content after tab switch.
**Where it breaks:** The rendered effect fires on `activeFilePath` change but the model still has old content (file load is async). The re-render uses stale model content. Fix: the `onDidChangeContent` listener on the model should catch the model.setValue() from file load — but only if the listener is attached to the NEW model, not the old one.
**Size:** Medium — needs real ContentPane with Monaco
**Verification:** Open file A, toggle to rendered mode, verify A's content in rendered view. Switch to file B via openDoc. Assert rendered view now shows B's content (check for a unique string from B, absence of A's unique string).

### T-0320-RR-02: External file change re-renders in rendered mode

**Flow:** Agent edits file → file watcher fires → onFileChanged callback → model.setValue → onDidChangeContent → re-render
**Subsystems:** file watcher → IPC → ContentPane onFileChanged handler → Monaco model → renderMarkdown
**Expected:** Rendered view updates live when file changes externally.
**Where it breaks:** `suppressExternalRef` set from a recent save blocks the external change callback. Or the onDidChangeContent disposable was created for the old model and doesn't fire for the new one.
**Size:** Medium — needs real filesystem + watcher
**Verification:** Open file in rendered mode. Write new content to file on disk. Assert rendered view updates to show new content within watcher debounce window (~500ms).

### T-0320-RR-03: Tab switch in edit mode does NOT trigger re-render

**Flow:** leftPaneRenderMode=edit → openDoc(newPath) → file loads → no render call
**Subsystems:** store (leftPaneRenderMode) → ContentPane rendered effect guard
**Expected:** When mode is edit, switching tabs does NOT call renderMarkdown. No wasted work.
**Where it breaks:** Effect runs but the `if (leftPaneRenderMode !== 'rendered') return` guard is missing or wrong.
**Size:** Small
**Verification:** Mock renderMarkdown. Set mode to edit. Switch tabs. Assert renderMarkdown NOT called. (Can be tested at store level — mode doesn't change, effect deps don't trigger render.)

## 3. Scroll sync

### T-0320-SS-01: Edit → rendered — cursor visible, y-coordinate matching

**Flow:** Cmd+J → read cursor line → compute screen y → find closest data-source-line element → set rendered scrollTop
**Subsystems:** Monaco editor (cursor position, getTopForLineNumber, getScrollTop) → data-source-line DOM lookup → rendered div scrollTop
**Expected:** Content at cursor's screen y in editor appears at same screen y in rendered view.
**Where it breaks:** `getTopForLineNumber` returns pixel offset from document top, not viewport — must subtract `getScrollTop`. Or `data-source-line` elements are sparse (only block-level) — cursor between two markers snaps to wrong one. Or rendered element height differs from editor line height → visual mismatch (acceptable per spec — "same area" not "same pixel").
**Size:** Medium — needs real Monaco + real rendered DOM
**Verification:** Open long document. Scroll to line ~50. Place cursor. Toggle to rendered. Read rendered scrollTop. Find the element with matching data-source-line. Assert `element.offsetTop - scrollTop` is approximately equal to cursor screen y (within ~50px tolerance for block-level granularity).

### T-0320-SS-02: Edit → rendered — cursor off-screen, fallback to viewport top

**Flow:** Cursor at line 10, viewport scrolled to line 80 → cursor screen y is negative → fallback: use `getVisibleRanges()[0].startLineNumber`, screen y = 0
**Subsystems:** Monaco editor (getVisibleRanges, getTopForLineNumber, getScrollTop) → fallback logic → data-source-line lookup
**Expected:** Rendered view aligns to the topmost visible editor line, not the invisible cursor.
**Where it breaks:** Cursor y check wrong — negative y means above viewport, y > viewport height means below. Must check both. Or `getVisibleRanges()` returns empty (no visible ranges) — edge case when editor is hidden.
**Size:** Medium — needs real Monaco viewport
**Verification:** Open long document. Place cursor at line 1. Scroll editor to line 80 (cursor now off-screen above). Toggle to rendered. Assert rendered view shows content from around line 80, not line 1. Also test cursor below viewport (cursor at line 200, viewport at line 50).

### T-0320-SS-03: Rendered → edit — topmost visible source line

**Flow:** Cmd+J from rendered → find topmost visible `data-source-line` element → set editor cursor → revealLineInCenter
**Subsystems:** rendered div (scrollTop, element positions) → data-source-line attribute → Monaco editor (setPosition, revealLineInCenter)
**Expected:** Editor opens with cursor at the section the user was reading. That line is centered in the viewport.
**Where it breaks:** "Topmost visible" means `element.offsetTop >= renderedDiv.scrollTop` — first element whose top is at or below the scroll position. If all elements are below viewport (scrolled past end), picks the last one. If no data-source-line elements exist (empty document), should gracefully do nothing.
**Size:** Medium — needs real rendered DOM with scroll
**Verification:** Open long document in rendered mode. Scroll to middle. Toggle to edit. Assert editor cursor line number matches the data-source-line of the topmost visible rendered element. Assert that line is visible in editor viewport (not scrolled away).

### T-0320-SS-04: Round-trip — edit → rendered → edit preserves position

**Flow:** Cursor at line N → Cmd+J → rendered at section N → Cmd+J → cursor back at line N
**Subsystems:** All of SS-01 through SS-03 composed
**Expected:** Toggle twice → cursor returns to original line (or very close — within the data-source-line block).
**Where it breaks:** Accumulation error: line 85 → rendered shows section starting at line 82 (closest data-source-line) → edit goes to line 82. Each round-trip drifts toward the nearest block boundary. Acceptable per spec ("same area"), but should not drift more than one block.
**Size:** Medium
**Verification:** Place cursor at known line. Toggle to rendered. Toggle back to edit. Assert cursor line is within ±5 lines of original. Repeat once more — assert no further drift.

### T-0320-SS-05: data-source-line closest-match algorithm

**Flow:** Given anchor line N, find rendered element with closest `data-source-line`
**Subsystems:** Pure DOM traversal logic (no Monaco, no real rendering)
**Expected:** If exact match exists, use it. If not, use the element with the largest `data-source-line ≤ N` (prefer the block that CONTAINS the line, not the block after it).
**Where it breaks:** Algorithm uses `Math.abs` difference → picks the block AFTER the line if it's numerically closer. Should prefer the block that started before the line (the one the user is "inside").
**Size:** Small — can test with fake DOM elements
**Verification:** Create a div with children having data-source-line 1, 5, 12, 20. Query for line 7 → should return element with line 5 (not 12). Query for line 12 → exact match. Query for line 25 → returns 20 (last element).

### T-0320-SS-06: Scroll sync with empty document

**Flow:** Toggle rendered on empty doc → no data-source-line elements
**Subsystems:** scroll sync lookup → empty result
**Expected:** No crash. Rendered view shows at scrollTop 0. Edit → rendered and rendered → edit both gracefully do nothing.
**Where it breaks:** querySelector returns null, code tries to read `.offsetTop` → TypeError.
**Size:** Small
**Verification:** Open empty file. Toggle to rendered. Assert no error. Toggle back. Assert cursor at line 1.
