# v0 — stories

Concrete scenarios that define "working."

## S1: Monaco boots in extension

* user installs extension, clicks icon → side panel opens
* Monaco editor loads without console errors
* napkin-markdown language registered (heading, //, //A: colored)
* if this fails, nothing else matters

## S2: clone .nap repo, see it in nav tree

* terminal tab is active, prompt visible
* user types: `git clone https://github.com/org/project-nap`
* terminal shows: `Cloning into 'project-nap'... done.`
* nav tree populates:
  * 20-architects/ section with architect entries
  * 30-napkins/ section with napkin entries + status labels
* napkin entries sorted by number (0100, 0200, ...)

## S3: open chapter, read comfortably

* user clicks `01-copy-pipeline.md` under a napkin in nav tree
* tab bar switches to editor
* Monaco loads file content from LightningFS
* napkin-markdown tokenizer active:
  * `# heading` → bold, bright
  * `* bullet` → dimmed marker, normal content
  * `//DU: comment` → role color
  * `**bold**` → bold
* lightBlue theme: cool blue tint (#f0f4f8), comfortable at 600px width
* word wrap on, no minimap, no line numbers

## S4: add comment, verify from terminal

* editor showing a chapter (from S3)
* user types `// looks good` on a new line
* text appears green (comment token)
* wait 1 second (auto-save debounce)
* user switches to terminal tab
* types: `cat /home/user/project-nap/.nap/nepics/.../01-copy-pipeline.md`
* output includes `// looks good`
* proves: editor writes to same LightningFS that terminal reads

## S5: terminal edit, verify in editor

* terminal tab active
* user types: `echo "// terminal was here" >> /home/user/project-nap/.nap/nepics/.../01-copy-pipeline.md`
* user switches to editor tab, reopens the file (or file already open)
* editor content includes `// terminal was here`
* proves: bidirectional LightningFS sharing

## S6: git workflow from terminal

* after editing (S4)
* user in terminal:
  ```
  cd project-nap
  git status     → shows modified file
  git add .
  git commit -m "review comments"   → shows commit hash
  git log --oneline -1              → shows "review comments"
  ```
* no commit button — terminal IS the git UI

## S7: shift-enter continuation

* editor showing a napkin file
* cursor at end of line: `  * some bullet point`
* user presses Shift+Enter
* new line appears: `  * ` (same indent + bullet)
* cursor after the `* `
* on a `//DU:` line, Shift+Enter continues with `//DU: `

## S8: click file:line link → GitHub

* editor showing a chapter with link: `[copy_document.ts:51](/modules/server/.../copy_document.ts#L51)`
* link styled: underlined, link color from theme
* user Cmd+clicks the link
* main browser tab navigates to: `https://github.com/{owner}/{main-repo}/blob/{branch}/modules/server/.../copy_document.ts#L51`
* note: navigates to MAIN CODE REPO, not the .nap repo

## S9: navigate between chapters

* editor showing `01-copy-pipeline.md`
* chapter links to `02-id-universe.md` (relative .md link)
* user Cmd+clicks → editor loads `02-id-universe.md` from IDB
* same napkin-markdown styling, same theme

## S10: lightBlue theme applied

* user opens extension side panel
* editor background: #f0f4f8 (cool blue tint)
* nav tree and tab bar use same palette via --nap-* CSS variables
* all token colors match v3's lightBlue theme rules

## S11: auth for private repo

* user opens extension popup (not side panel)
* pastes GitHub PAT into settings field
* clicks "test" → shows success (API call to github.com/user)
* returns to side panel terminal
* `git clone https://github.com/org/private-nap` → succeeds
* without token: clone would fail with 401

## S12: nav tree structure matches nap.app

* after cloning a .nap repo with:
  * `20-architects/001-architect/` (prompt.md, scratch/)
  * `30-napkins/0100-feature/` (.napkin.nap.json with status "doing", agents/)
  * `30-napkins/0200-other/` (status "backlog")
* nav tree shows:
  * architects section: 001-architect (expandable → prompt.md, scratch/)
  * napkins section: 0100-feature (doing), 0200-other (backlog)
  * 0100-feature expandable → .nap.md, agents/
* matches nap.app sidebar layout, not raw filesystem listing

## S13: panel survives tab navigation

* side panel open with cloned repo and file in editor
* user navigates to a different GitHub page in main tab
* side panel stays open, editor content preserved
* user navigates back to PR page
* everything still there — IDB persists, panel is independent of main tab
