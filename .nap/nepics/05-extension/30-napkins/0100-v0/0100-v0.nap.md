# v0 — side panel for .nap repos

* what it is
  * Chrome side panel alongside GitHub
  * reads .nap repo — separate from main code repo, gitignored there, own GitHub remote, always on main
  * mini-books inside .nap guide reviewer through code via file:line links
  * read book → click link → main tab shows the code in main repo

* two repos, one bridge
  * .nap repo → cloned into IDB (small — markdown, napkins, agents)
  * main code repo → never cloned, linked via GitHub blob URLs
  * extension bridges .nap (local, editable) with code (remote, view-only on GitHub)
  * // comments edited locally → pushed back via terminal git

* side panel layout (~900px on 1500 screen)
  * nav (left, ~300px): nap-style tree
  * content (right, ~600px): tab bar → terminal | editor
  * resize handle between nav and content
  * book is the main surface — 600px, comfortable reading

* nav tree (nap.app style, not raw filesystem)
  * reads cloned .nap repo from LightningFS
  * same structure as nap.app sidebar:
    * architects (20-architects/) — expandable
      * scratch files, prompt.md, response.md
    * napkins (30-napkins/) — expandable
      * chapters (numbered .md)
      * agents (expandable)
    * docs (10-docs/), feedback (15-feedback/)
  * click .md → opens in editor
  * needs to understand .nap directory conventions, not just list files

* terminal (proven — packages/bash-poc/)
  * wterm + just-bash + lightning-fs + isomorphic-git
  * clone .nap repo → files appear in nav tree
  * bash: ls, cat, cd, grep, echo, pipes, heredocs
  * git: log, status, diff, add, commit, push
  * terminal IS the git UI — no commit button
  * shares one LightningFS instance with editor and nav

* editor (key technical risk — unproven)
  * Monaco with napkin-markdown tokenizer (copy from v3, not import)
  * data flow: lfs.readFile → monaco.createModel → edit → debounced lfs.writeFile
  * one LightningFS instance → terminal and editor see same files
  * config:
    * word wrap, no minimap, no line numbers
    * light theme default
    * editable — // comments inline
    * shift-enter continuation (copy from v3)
  * Monaco workers in extension context
    * workers are Web Workers (page-scoped), not Service Workers
    * no LightningFS mutex concern — workers process text, never touch fs
    * but: extension CSP may block blob: URLs Monaco uses to load workers
      * fix: bundle workers as extension assets, set MonacoEnvironment.getWorkerUrl
      * this is the scariest unknown — if Monaco can't boot, everything stalls
  * LightningFS ↔ Monaco read/write
    * probably straightforward (both async, both work with strings)
    * but never tested together — prove early

* link routing
  * tokenizer: underline + link color for file paths and markdown links
  * Cmd+click in editable mode
  * routes:
    * file:line → GitHub blob URL in main tab (main code repo, not .nap repo)
    * .md → load chapter in editor (from IDB)
    * .ts/.tsx → GitHub blob, single-click reuses tab, double-click opens new
    * https:// → new tab
  * content script on github.com handles navigation requests from side panel

* auth
  * PAT in chrome.storage.sync
  * settings popup: paste token, test connection
  * isomorphic-git onAuth callback
  * public repos work without token

* design
  * use nap.app lightBlue theme (packages/v3/src/renderer/themes.ts)
    * editor bg #f0f4f8, text #2e3440, cool blue tint
    * light only — no dark mode switching
    * same token rules: heading, bullet.marker, bold, inline-code, comment, comment.role
    * same shell CSS variables (--nap-bg, --nap-text, etc.)
  * nav tree matches nap.app sidebar style
    * napkin entries with status labels (doing, backlog, done)
    * agent icons, expandable tree nodes
    * monospace, sparse, flat visual weight

* extension plumbing
  * Manifest V3, side_panel permission
  * background.ts: register side panel
  * content.ts: github.com page detection + link navigation
  * side-panel.html + side-panel.ts: the app (terminal, editor, nav, tab bar)
  * packages/extension/ in monorepo

* shared LightningFS (the glue)
  * single instance, three consumers: terminal, editor, nav tree
  * terminal writes (git clone, echo >>) → editor/nav see changes
  * editor writes (auto-save) → terminal sees changes (cat, git status)
  * no watcher needed — consumers read on demand from same IDB

* testing
  * Playwright + Chrome with --load-extension
  * extend POC patterns (cmd() helper, prompt counting)
  * fixture: real small public .nap-style repo
  * prove first:
    * Monaco boots in extension sandbox (CSP + workers)
    * Monaco reads from LightningFS, edits save back
    * terminal sees editor changes (cat shows edited content)
    * nav tree reflects cloned repo structure

* what's NOT in v0
  * rendered mode (Cmd+J)
  * workflowy zoom / setHiddenAreas
  * heading size decorations
  * diff layers (agent commit vs user edits)
  * concurrent cursors
  * bullet anchors, cross-file linking
  * nap.app integration
