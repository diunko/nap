# v0 — spec

Constraints the implementer can't derive from the napkin or codebase alone.

## Two-repo architecture

* the cloned repo (.nap) is NOT the repo that file:line links point to
  * .nap repo → cloned into IDB, editable, pushed back via terminal
  * main code repo → never cloned, only linked via GitHub URLs
  * file:line in a mini-book resolves to the MAIN code repo, not the .nap repo
  * link URL: `https://github.com/{owner}/{repo}/blob/{branch}/{path}#L{line}`
  * {owner}/{repo} for links comes from the mini-book content, not from the cloned repo
* v0: user manually provides .nap repo URL (git clone in terminal)
  * no auto-detection of which .nap repo matches which code repo

## Extension CSP blocks Monaco by default

* Monaco loads workers via blob: URLs — Chrome extension CSP blocks this
* manifest.json must explicitly allow:
  ```json
  "content_security_policy": {
    "extension_pages": "script-src 'self'; worker-src 'self' blob:;"
  }
  ```
* alternative if blob: still fails: bundle editor.worker.js as extension asset, configure:
  ```typescript
  window.MonacoEnvironment = {
    getWorkerUrl: (_id, _label) => chrome.runtime.getURL('editor.worker.js')
  };
  ```
* this is the scariest unknown — prove it boots before building anything else

## LightningFS: one instance, two access patterns

* exactly ONE LightningFS instance, created at panel startup
* store name must be stable across panel reloads: use `'nap-ext'`
* terminal consumes via IFileSystem adapter (from bash-poc fs-adapter.ts)
  * just-bash requires the adapter — it can't use lfs.promises directly
* editor and nav tree consume via lfs.promises directly — no adapter needed
  * don't route Monaco reads through the adapter — unnecessary indirection
* isomorphic-git consumes the raw LightningFS instance (not the adapter)
  * same as bash-poc: `git.clone({ fs: lfs, ... })` — lfs, not the adapter

## Nav tree is not readdir

* the tree must interpret .nap/ directory conventions:
  * `20-architects/{NNN}-{name}/` → architect entry
  * `30-napkins/{NNNN}-{name}/` → napkin entry
    * read `.napkin.nap.json` for status label (doing, backlog, done)
    * nested `agents/{NNN}-{role}-{subject}/` → agent entries under napkin
  * `10-docs/`, `15-feedback/` → sections
* sort by numeric prefix (0100 before 0200, 001 before 002)
* display status labels next to napkin names
* architect and agent entries show: prompt.md, response.md, scratch/ contents
* napkin entries show: .nap.md, .spec.md, .stories.md, .test.md, and agent subdirs

## Terminal gotchas (from bash-poc)

* Buffer polyfill required BEFORE any isomorphic-git import:
  ```typescript
  import { Buffer } from 'buffer';
  (globalThis as any).Buffer = Buffer;
  ```
* wterm CSS is NOT in the npm package — must inline or copy terminal.css
  * without it: cursor invisible, rows unstyled, terminal appears blank
* CORS proxy required for git clone: `cors.isomorphic-git.org`
* `/dev` doesn't exist in LightningFS — just-bash may emit ENOENT stderr noise (cosmetic)

## Theme contract

* copy ThemeDef + theme objects from packages/v3/src/renderer/themes.ts
* default: lightCream (editor bg #fdf6e3, warm paper)
* dark: dark theme (editor bg #1e1e1e)
* token theme rules must match napkin-markdown tokenizer token names:
  * heading, bullet.marker, bold, bold.marker, inline-code, comment, comment.role, source
* shell CSS variables (--nap-bg, --nap-text, --nap-border, etc.) applied on panel root
  * nav tree, tab bar, and chrome use these variables — not hardcoded colors
* detect GitHub theme: content script reads `<html data-color-mode>` or body classes
  * sends message to side panel → panel switches theme

## Playwright can't open side panel directly

* chrome.sidePanel API has no Playwright equivalent
* workaround options:
  * register keyboard shortcut via chrome.commands → Playwright sends the shortcut
  * navigate directly to the side panel page URL (chrome-extension://{id}/side-panel.html)
    * this loses the side panel frame but lets you test the app in isolation
* the bash-poc test patterns (cmd() helper, prompt counting) carry forward
* fixture: need a real small public repo with .nap/ structure
  * must have: 20-architects/, 30-napkins/ with numbered .md chapters, .napkin.nap.json
